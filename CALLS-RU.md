# Звонки в Рядом 2.4

## Windows и сервер 2.5.2: повторный звонок и лимит попыток

При частом повторе вызовов прежний сервер отказывал уже после четырёх попыток за минуту. Окно Windows сразу закрывалось, а обновление переписки затирало объяснение в строке состояния. Теперь разрешены 12 попыток за скользящую минуту; отказ содержит оставшееся время ожидания. При отказе или завершении со стороны собеседника окно остаётся открытым с причиной, кнопкой «Позвонить снова» и отсчётом при ограничении частоты. Во время отсчёта повторные клики не отправляют новые вызовы. Закрытие окна сохраняет отсчёт до выхода из аккаунта.

У каждой исходящей попытки есть идентификатор. Запоздавший ответ, повторное событие начала и завершение предыдущего звонка не сбивают текущий разговор. Закрытие окна крестиком освобождает состояние без повторного вызова Close из обработчика Closing. Проверены входящий разговор и пять обратных вызовов подряд с двусторонним искусственным PCM и отдельным подключением уведомлений Android. Тесты не включают физические микрофоны.

## Android 2.5.1: эхо из динамика телефона

Звонки используют источник `VOICE_COMMUNICATION`, предназначенный для речевой связи и обработки эха, вместо обычного `MIC`. `AcousticEchoCanceler` включается для текущей сессии записи, а окно звонка показывает его фактическое состояние через `getEnabled()`. При смене динамика приложение повторно включает эффект. Если речевой источник не удаётся открыть, он полностью освобождается до попытки обычного микрофона; отказ в доступе к микрофону не обходится. Сохраняются чтение PCM16 через short[] и последовательное освобождение аудио из 2.4.1.

На Android 12+ при выключенной громкой связи подключённая гарнитура имеет приоритет перед разговорным динамиком. Кнопки громкости во время вызова регулируют разговор. На ПК для этого исправления обновление не требуется.

Установите APK поверх прежнего. Позвоните с ПК в наушниках на Android: проверьте, что на телефоне написано «Эхоподавление включено», и сравните обычный динамик с громкой связью. Эффективность зависит от аудиосистемы телефона; компиляция и тесты формата PCM не заменяют акустическую проверку на устройстве. Если эффект недоступен, приложение показывает это, не выдавая запрос на включение за успешное подавление эха.

Основание выбора источника: [Android VOICE_COMMUNICATION и preprocessing](https://source.android.com/docs/core/audio/implement-pre-processing), [AcousticEchoCanceler](https://developer.android.com/reference/android/media/audiofx/AcousticEchoCanceler).

## Обновление 2.4.1 для Android и Windows

Исправлены чтение и отправка PCM16 на Android, освобождение аудиоустройств перед повторным звонком и обработка запоздавших ошибок завершённого вызова. На Android виден уровень микрофона и получение звука; на Windows — уровень микрофона и собеседника, а также выбор динамика. Обновите оба приложения. Для проверки позвоните, завершите разговор и сразу позвоните ещё раз. Если на ПК виден ненулевой уровень собеседника, но его не слышно, выберите нужное устройство в списке «Динамик».

Автоматическая проверка использует реальные сетевые клиенты Android и Windows с искусственным PCM16: три последовательных звонка и 90 кадров в каждом направлении. Она не заменяет проверку физических микрофонов и динамиков. Сервер сохраняет вызов при кратковременной ошибке повторной проверки сессии; отозванная сессия отключается сразу, а отсутствие успешной проверки ограничено тремя минутами.

Оба собеседника обновляют приложение и входят в свои аккаунты. Откройте переписку и нажмите «Позвонить» (значок трубки на iPhone). У собеседника появится входящий вызов: «Принять» или «Завершить». При первом звонке разрешите микрофон. В разговоре можно отключить микрофон, на телефоне — переключить громкую связь.

На iPhone и Android «Рядом» должен оставаться на экране у обоих собеседников. Уход в другое приложение или блокировка телефона завершает вызов. Системные входящие звонки при закрытом «Рядом» пока не реализованы. На ПК приложение должно быть запущено. Для Windows рекомендуются наушники, чтобы собеседник не слышал эхо.

Используется существующий бесплатный сервер Render; платные сервисы не добавлены. Если сервер спит, первое подключение может занять около минуты. Доступность и квоты бесплатного хостинга продолжают действовать.

## Передача звука

Аутентифицированный WebSocket `/api/calls`, протокол 1. Звук: PCM signed 16-bit little-endian, 16000 Hz, mono. HTTPS/WSS защищают соединение с сервером; это не сквозное шифрование. Сервер пересылает звук только между принявшими звонок устройствами, не сохраняет и не записывает разговоры. Около 32 КБ/с звука в каждом направлении. Буферы ограничены; при плохой связи старые кадры отбрасываются вместо накопления задержки.

Микрофон включается только после принятия вызова. Один разговор на аккаунт, тайм-аут вызова 35 секунд, повторная проверка сессий, отключение при выходе, отклонении, обрыве связи и потере аудиофокуса. При нескольких открытых устройствах отвечает первое принявшее.

## Сборка

Windows: `windows/build.ps1`. iPhone: существующая macOS GitHub Actions сборка, IPA без подписи для Sideloadly. Android: `android/build.sh`, прежний ключ подписи из защищённого кеша GitHub Actions. Сервер: `npm ci --omit=dev && npm test`, затем `npm start`. В Render команда сборки должна включать установку npm зависимостей.

Android использует Java-WebSocket 1.6.0 и SLF4J 2.0.13 (MIT). Артефакты скачиваются с Maven Central с проверкой SHA-256. Тексты лицензий включены в APK в assets. Сервер использует ws 8.22.0 (MIT), версия и integrity зафиксированы в package-lock.json.
